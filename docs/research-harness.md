# 从流程图模板到论文制图闭环

## 为什么同一个模型仍会画出不同质量的图

模型名称只是一个条件。任务材料、可用工具、可调整的图形范围，以及模型能否看到渲染结果并继续修改，都会影响质量。

原业务流程 Demo 的输入是最多 8,000 字符的简述，输出是 3–6 个阶段的 `FigurePlan`，程序再生成三种固定布局。它适合 SOP 演示，但不等于“阅读长论文，重新设计研究主图”。不能用这个窄任务的耗时代表复杂论文制图。

研究入口新增的是可移植的任务工作流，不是复制某个平台的内部系统提示词。公开规则见 [`prompts/research_harness.md`](../prompts/research_harness.md)，工具实现见 [`demo_core/research_harness.py`](../demo_core/research_harness.py)。

| 环节 | 研究入口的实际行为 |
|---|---|
| 读材料 | 只读用户显式提交的文件；保留全部抽取文本及页码、来源与哈希，超限报错，不截取前 8,000 字符 |
| 看原图 | 可按页读取 PDF 像素，检查原图、公式和案例；抽取文本不被包装成完整视觉理解 |
| 定内容 | 记录一句话结论、阅读顺序、核心关系、原文依据、图注及不确定项 |
| 探索版式 | 开放场景坐标，不固定四组卡片或图标数量；新主图探索六个不同粗稿，覆盖三类结构和两档密度 |
| 排精确内容 | 独立的矢量文字、公式、图形、图片、端点和连线；统一实际字体测量与渲染 |
| 看图修改 | 模型看到当前 PNG 和检查结果，可调整局部或重排整体，多轮继续直到预算用完 |
| 再审一次 | 单独的 Sol 审图调用接收原始材料、已读取的 PDF 页、当前图与证据绑定，不复述主绘图者的结论 |
| 交付 | 当前版本检查和审图都通过后才给正式 ZIP；失败保留草稿与错误，不标记完成 |

自动检查覆盖文本溢出、纸宽字号、公式可读尺寸、图片实际 alpha 占用、连线穿字、箭头尖端遮挡、PDF 页数和字体。它不能代替作者判断科学内容和最终审美。

## 本地使用

从仓库根目录运行，使用标准 OpenAI Responses API，默认服务地址不变。需要 Python 依赖及 Poppler、Fontconfig、Cairo 和可用字体；Dockerfile 提供对应系统依赖。

```bash
export OPENAI_API_KEY="your-api-key"
python -m demo_core.research_harness \
  --source paper.pdf \
  --brief "阅读这篇论文，为技术汇报设计一张清晰的机制主图。准确区分训练、推理、输入和控制信号。" \
  --style-image approved_style.png \
  --output demo/output/research-first
```

`--source` 可以多次传入 PDF、文本和代码资料。素材清单通过 `--asset-manifest assets.json` 显式传入；每项含 `id`、`path`、`kind`、`meaning`，图片路径仅由调用者登记，模型不能读取任意路径。输出目录必须是新目录。

继续一张已有草稿时，可传 `--initial-scene candidate.scene.json --initial-design design.json --narrow-revision`。配合可重复的 `--editable-id` 限定允许改变的元素：程序会锁住其余元素、画布和顺序，防止局部修订破坏已确认内容。来源与素材仍须显式提供；继续修订有新的独立计时，不重写上一轮的失败记录。元数据中的证据绑定可独立修正，但仍须重新通过审查。

默认最多 24 次模型调用、20 分钟循环预算、`medium` 推理强度；检查预算发生在调用之间，单次请求可能使墙钟时间略超预算。服务端超时也计入本次尝试。`--narrow-revision` 只用于明确的小范围修改，免除六粗稿要求，不免除内容、渲染与审图检查。

可分别加 `--allow-reference-search` 和 `--allow-image-generation` 开启参考搜索/导入或首次生成图标。默认都关闭。搜索支持 Commons 与 `official-brand`：前者把模型选择的检索词发送给 Commons，后者在已核验的官方目录中查询，再按注册 ID 下载。图标生成会增加图像费用，最多两次尝试；真实品牌不能通过生图重绘。图标调用仍由同一个 Sol 身份网关发起，图像引擎另记为 `gpt-image-2`；原始材料、当前设计与已读页面会进入该步骤。复杂照片仅做保守本地处理，不冒充已完成语义分割。使用 Commons 图片时，渲染器自动追加来源、作者、许可和裁切说明，不依赖模型记得署名。网页研究入口当前只接显式上传素材；这些联网选项通过命令行开放。官方素材、原生 SVG 与局部编辑的完整例子见 [分层编辑](layered-svg-editing.md)。

需要网页入口时：

```bash
export FIGUREFLOW_ENABLE_RESEARCH=true
python app.py
```

打开底部“论文主图（实验）”。默认不开启，公开演示模式强制禁用；公网绑定必须有认证，不允许匿名分享。上传文件、素材和风格图片会用于在线模型分析，须在提交前明确确认。不要上传未经授权的内部材料。

## 模型与记录

所有研究理解、布局规划及审图调用固定请求 `gpt-5.6-sol`。首次返回的合法 Sol 模型名（含日期版本）会被锁定；后续标识变化即停止。服务端未报告身份的调用不会被当作已核验，也不能进入正式交付。

这是对**请求与服务端自报身份**的核验，不能独立证明中间服务实际部署的模型权重。图像生成引擎与语言模型不是同一概念；旧流程的无文字图标使用单独标注的 `gpt-image-2`，不能把它写成 Sol 的文本调用。

运行目录保留来源清单、公开提示词和实现文件哈希、逐轮操作、每次调用的输入规模/图片数量/身份/用量，以及每个场景版本的检查结果。正式包的 `model_audit.json`、`manifest.json`（包括嵌套素材来源）和 `design.json` 副本递归去掉服务商 `response_id`，保留模型标识、用量、输入哈希等；完整记录留在本地。场景与补丁不重写，以保持重放哈希。字段脱敏不等于公开发布许可，用户自行写入的敏感内容仍须单独检查。

标准 Responses 路径会保留并重放原始 output items，而非只拼接最终回答文本。这遵循官方[跨轮上下文与推理状态说明](https://developers.openai.com/api/docs/guides/reasoning#preserve-reasoning-without-stored-responses)。兼容服务若不返回同等状态，不能声称已经验证与官方服务完全等价。

## 当前边界

- 研究入口支持显式素材、源页查看、布局与多轮修订。记录运行耗时时，应明确是否包括图标首次生成、在线搜索和人工选择；素材已准备好的渲染耗时不能代表端到端用时。
- 自主参考导入、图标生成与本地处理默认关闭。单元测试使用受控接口验证契约和安全边界，不是在线成图质量或速度实验。
- 正式 PDF 会按指定纸宽导出并检查。插入具体论文后的浮动体、图注和页面布局仍需在论文工程内编译验收。
- `automated_review_passed` 仅表示程序检查和同模型的独立审图调用通过，始终保留 `human_approval: pending`。
- 这仍是实验入口；未通过质量验收的运行必须计为失败或草稿，不参与“合格成图平均耗时”统计。

发布前应对图、引用、论文许可及运行日志另做脱敏和分享范围检查。研究入口本身没有发布工具。
